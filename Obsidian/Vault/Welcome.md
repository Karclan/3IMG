# Welcome

Welcome to the Vault. This is our source of documentation for our projects. It'll contain any and all useful information. Whether that be specific project design or containing tips and information about various processes, game engines, design ideas, or whatever else we think is useful.

If you are new to [[Obsidian]] there are some very useful tutorials we can link and reference. 

The overall principle is that [[Obsidian]] is a note taking app. In [[Obsidian]] there are about 3 main concepts (at least with how I use it).

1. Notes
2. Tags
3. Links

### Notes

Notes are files like this. They use [[Markdown]] as a format for displaying information. At the top of the files you can also include some [[YAML]] for things like properties.

Tags, tags are defined with a `#tagname` and we have a few we use to help us catalogue notes. Such as "In Progress", "Completed" "Needs Revision". 

Links, links let us create pathways between notes. Simply by including a note inside another note the visual graph will display a link between them. Also with the settings we have links are visible at the bottom of the file they appear in. This is useful to help group similar notes and concepts together.

Creating a new note can be as simple as right clicking on the folder view and adding a note or we have the hotkey `ctrl+n`.

#### Templates
When creating new notes, the default location is "6 - Main Notes", a good workflow is to try use our templates as much as possible. First start by naming the note then press "Alt + T" to open the Templates menu. Select the correct template for the note, it will typically be "New note template". Then go ahead and fill in the note as you want. There are no fixed number of templates and we can easily adjust and modify them. However, any note created prior to a change of a template will not have it's contents updated to match. There might be a solution for this but I'm not aware of it yet.

#### Topics
Topics are basic notes which act as a grouping method. Such as "Godot" or "Fish" or "Castell likes feet". There is no specific rule as to what is and isn't a topic. However, it's useful to keep Topics easy to understand from their name alone. 

Topics are then linked in notes via `[[note name]]`. 

A Topic can become an Index once it has about 5+ links. We can decide then to add more information to that new Index which we might find useful.

#### Daily Notes
Daily notes aren't meant to be included in the [[GitHub]] repository. The intention is they can be used for ourselves locally to keep track of any particular notes we have. We can then move those notes over to main notes if we want. However, we could potentially do some system of daily notes that we could share them all amongst us but we need to be careful with names and file conflicts.
